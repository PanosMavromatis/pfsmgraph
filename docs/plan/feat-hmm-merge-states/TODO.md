  - [x] Transcribe `hmm-param.lsh:218-369` into a per-array statement of the result, including the `old-state-numbers` remap and which assignments later ones overwrite
    > **Note:** Notation: `a < b` are the two states after the swap at `:229-234`. `T`, `O` and `init` are the old arrays; `T'`, `O'` and `init'` the new ones. `o(i)` maps a new index to its old one: `o(i) = i` for `i < b`, else `i + 1` (`:255-258`). New index `a` is still old `a`. Later assignments overwrite earlier ones.
    > **`init'`:** `init'[i] = state_p[o(i)]` for every `i` (`:262`, the defect goal 2 examines). Then `init'[a] = init[a] + init[b]` (`:272-273`) overwrites it for the merged state only. Before the fix, the vector sums to `Σ_{i≠a,b} state_p[i] + init[a] + init[b]`.
    > **`T'`:** first the old matrix minus row and column `b`, remapped through `o` (`:264-265`). Three blocks then overwrite parts of it. **Inbound** (`:276-294`), for every new `j` *including `a`*: `T'[j,a] = T[o(j),a] + T[o(j),b]`. **Outbound** (`:297-326`), for every new `j` *including `a`*: `T'[a,j] = p₁·T[a,o(j)] + p₂·T[b,o(j)]`, where `pᵢ = safe-/(state_p[i], state_p[a] + state_p[b])`. **Self-loop** (`:329-361`): `T'[a,a] = p₁·(T[a,a] + T[a,b]) + p₂·(T[b,a] + T[b,b])`, so the four arcs among the pair collapse into one.
    > **Overwrites in `T'`:** cell `(a,a)` is written four times (generic, inbound, outbound, self), and only the last survives, so the inbound and outbound writes to it are dead. Every other cell in column `a` is final after the inbound block, and every other cell in row `a` after the outbound block. Each row `j ≠ a` still sums to one, since its entries into `a` and `b` are added. Row `a` sums to `p₁ + p₂`: one when `state_p[a] + state_p[b] > 0`, and **all zero otherwise**.
    > **`O'`:** the remapped copy first, then the same three blocks, each the transition-weighted average of the fibres it collapses. Inbound: `O'[j,a] = safe-/(T[o(j),a]·O[o(j),a] + T[o(j),b]·O[o(j),b], T'[j,a])`. Outbound: `O'[a,j] = safe-/(p₁·T[a,o(j)]·O[a,o(j)] + p₂·T[b,o(j)]·O[b,o(j)], T'[a,j])`. Self: `O'[a,a]` averages the four fibres `aa, ab, ba, bb` with weights `p₁t₁₁, p₁t₁₂, p₂t₂₁, p₂t₂₂`, divided by `T'[a,a]`. Cell `(a,a)` has the same fourfold overwrite as in `T'`.
    > **`state_p`, `state_entropies`:** left as zero arrays, as in the split. Under ADR 0017 they are computed rather than stored, so this dissolves. The `state_p` the merge *reads* is the stored slot. That is current only because `try-merge-with-update` and `suggest-merge` refuse a `dirty` trainer, so it equals the port's value computed from `transition_p`.
    > **Three consequences.** There are **no random draws**, so `_merge_states` needs no `rng`. The pair is **unordered**: because of the swap, `merge(a, b)` and `merge(b, a)` are identical. And **`a == b` is not checked here**: the check was commented out to make the method compile and moved to the trainer (`hmm-trainer.lsh:845-851`), so the port must reject it itself.
    > **Precision:** the original's locals and storage are single precision (`-float-`, `float-matrix`); the port runs in float64.

    > **Note:** The method has seven calls, guarding three kinds of zero. **`:290`, inbound fibre:** the denominator is zero exactly when `j` reaches neither `a` nor `b`; the arc is then dead and the fibre comes out zero, which `HMMParams` already exempts. **`:312-313` and `:345-346`, the weights:** `p-sum = state_p[a] + state_p[b]` is zero when neither state carries stationary mass. - [x] Decide the reducible-chain case
  > **Done:** A merge cannot create reducibility; its weights take structural zeros on transient states; and a reducible incumbent is detected structurally, by one closed-class helper that `stationary_distribution` and `_merge_states` share. The implementation is goal 5's new first subgoal.
  > **Q:** How should `_merge_states` keep stationary-solve rounding on transient states out of its weights `p₁`, `p₂`: structural zeros from the arc graph, a tolerance threshold, or clamping negatives only?
  > **A:** Structural zeros. Find the recurrent states from the arc graph (`T > 0`), use `state_p` there and exactly `0` elsewhere. Exact by construction and tolerance-free, and it is what the original's `safe-/` on `p-sum` assumed.
  - [x] Establish when a merge makes the chain reducible, and whether the merge's own `state_p` read can fail first
    > **Note:** **With exact weights, a merge never makes a chain reducible when the incumbent has a unique stationary distribution.** Scratchpad reference merge, 20k random sparse chains with `S` from 2 to 9 and transient states' `state_p` set to exactly 0. Pairs with at least one recurrent state: 257,995 of 257,995 results have a unique stationary distribution. Pairs of two transient states: all 23,463 give the all-zero row (goal 4). Why: when both states are recurrent, the merge contracts two states of the same closed class, which preserves reachability. When one is transient, its outbound arcs get weight 0 and its inbound arcs now enter the closed class.
    > **Note:** **Rounding breaks it.** `stationary_distribution` gives transient states values up to `1.8e-14` in magnitude, some negative (`-0.0`, `-8e-17`). As raw weights, two transient states make `p-sum` noise rather than zero, so the merge returns a new absorbing class, negative entries or an arbitrary row where exact arithmetic gives a zero row. Example: closed class `{2}`, transient states 1 and 4 with `state_p` `-0.0` and `6.8e-18`, so `p₂ = 1`. State 4's arcs lead only into the pair, so the merged state is absorbing. One transient state with a slightly negative value puts negative entries into row `a`. With raw weights, 2,061 of 33,396 merges went bad.
    > **Note:** **The merge's own read fails first for a reducible incumbent, but not reliably.** Of 254 reducible random chains, 236 raised `ValueError` and **18 were solved silently** with condition numbers 3e16 to 2e19. Example: closed classes `{2,4}` and `{3}` returned as `[0, -0, 0, 1, -0]`. So `core.md`'s claim that a reducible chain is reported as `ValueError` is true only most of the time. This is a defect in `_numeric.stationary_distribution` that predates the merge.
  > **Q:** What should happen when the incumbent passed to the merge is itself reducible: a shared structural helper that fixes `stationary_distribution` too, a check in the merge alone with the solve's defect deferred, or letting `state_p` raise?
  > **A:** A shared helper that fixes both. The closed-class pass goes in `_numeric`. `stationary_distribution` raises `ValueError` from it structurally, so the silent solves stop and `HMMParams.state_p` is reliable, and `_merge_states` reuses the same pass for its recurrent mask. `docs/api` and `core.md` follow the behaviour change.

  - [x] Decide where `safe_divide` is consumed and what a zero weight means
    > **Note:** **A zero weight means "no stationary mass", not "no occupancy".** When one state of the pair is transient, its weight is exactly 0 and its learned outbound arcs are discarded, as in the original. That is right for the cyclic concatenated stream the fixtures were trained on.

## Goals

- [x] Specify what `try-split`, `try-merge` and `suggest-*` do before writing code
  - [x] Transcribe `try-split` (`hmm-trainer.lsh:749-770`) and `try-merge` (`:858-881`): what is re-converged, with which stopping rule, and how `d` is chosen per trial
    > **Note:** The two are identical apart from the surgery line. Each one: (1) applies `split-state` or `merge-states` to the working `params`; (2) runs `update-data-p`, the forward pass whose unrounded bits become `data-p`; (3) sets `last-saved-d` to the incumbent's `d` and zeroes the cycle counters; (4) runs `run-converge`; (5) runs `suggest-d`, which is `minimize-int` over the total on `[1, 10000]` starting **from 3821 on every trial**, never warm-started from the incumbent's `d`; (6) runs `keep-d`; (7) runs `update-all ()`, which recomputes entropies, `data-p`, the **Viterbi path**, the rounded matrices at `d`, and `data-dl`/`model-dl`/`total-dl`. Nothing is returned: the result is `total-dl` together with the converged `params`, left in trainer state for the caller to copy.
    > **Note:** `run-converge` is the rule `baum_welch` already has, measured on `data-p`, which is the unrounded corpus length and so independent of `d`. `old-data-p` starts at the *candidate's* starting value, and batches run 10 cycles each; 3 consecutive changes under `0.1 × *factor*` (with `*factor*` = 1) stop it. So **the original's floor is 30 cycles**, it has no cap, and a split that starts at the incumbent's likelihood meets that floor exactly, which is ADR 0022 §4's problem.
  - [x] Transcribe `suggest-split`, `suggest-merge` and `suggest-move` (`:952-1073`): trial counts, draw order, ranking and tie-breaking
    > **Note:** **`suggest-split`** loops `s = 0..S-1` ascending, with `2 + int(*split-trials-per-state-p* · π_s)` trials per state. The constants are `*min-split-trials*` = 2 and `*split-trials-per-state-p*` = 0, with the comment "20, or even 50 if we want to be thorough", so every state gets 2 trials as shipped. `π_s` is read from `:model:state-p`, the incumbent, which stays fixed through the round because `reset-model` restores `params` (including `d`) from the model after every trial. Random draws happen only inside `split-state`, from one global stream, in (state, trial) order; EM and `suggest-d` are deterministic.
    > **Note:** **`suggest-merge`** tries every pair `a < b` in lexicographic order, one trial each, with no randomness: `S(S-1)/2` full re-convergences, each followed by a Brent search. **`suggest-move`** runs all merges and then all splits against one shared best, so a tie *between kinds* goes to the merge. At `S = 1` the merge loop is empty.
    > **Note:** **Ranking.** Each `suggest-*` keeps only the argmin under a strict `<`, so ties go to the first candidate in iteration order. `best-total-dl` starts at `1e100`, the same value as the impossible-model sentinel, so an impossible candidate can never be selected. **If every candidate is impossible, the `best-*` slots stay `()` and `idx-copy` fails**, so the original has no "no move possible" path. The winner is installed unconditionally, whether or not it beats the incumbent: accepting it is the user's `keep-model`, and rejecting it is `reset-model`. Every trial also appends its total to `<model>.trials.txt`.
  - [x] Mark every point where ADR 0022 or an earlier decision makes the port depart from the original
    > **Note:** **Departures.** (1) **The candidate**: `_split_state` follows ADR 0022 §1-3, and `_merge_states` fixes `:262`, weights by exact stationary mass, and refuses two transient states. The original's search results are therefore not reproducible. (2) **The EM floor**: ADR 0022 §4 needs one above the original's effective 30 cycles (the ADR measured 200 forced cycles), and `baum_welch` has no parameter for it today; goal 2 decides the mechanism. (3) **Unrounded length**: ADR 0022 §5 reports `_corpus_description_length` beside each total, where the original logged the total alone. (4) **Randomness**: one `Generator` per (round, state, trial) replaces the global stream (ADR 0022 Resolved). (5) **Impossible models**: `+inf` replaces `1e100`. Since results are ranked rather than reduced to an argmin, "every candidate impossible" becomes a well-defined result instead of a crash. (6) **Ranked results**: all candidates are returned rather than the winner being staged into mutable state. First-wins is kept as a **stable sort on the total over iteration order** (merges before splits in `suggest-move`), so that tie-break stays contract. (7) **No `reset-model`**: under ADR 0017 every candidate is built from the frozen incumbent, so a reset is structural. (8) **A refused merge**: `_merge_states` raises on two transient states, where the original built an all-zero row, so goal 3 decides whether such a pair is skipped or ranked as impossible, together with the merge-weight question. (9) **Dropped per trial**: the Viterbi path and entropy refresh (annotation only under ADR 0017), the `trials.txt`/`printf` output (training-log subgoal), and the `dirty` guards with the `-with-update` GUI wrappers (`hmm-trainer-view.lsh` migrates nowhere).
    > **Note:** **Faithful on purpose.** `run-converge`'s rule, and its quantity being the same function as the data half. `_suggest_d`'s Brent search from 3821 on every trial (a global scan is the loop's decision). A score that is only ever obtained by calling the total. All-pairs merging, including its quadratic cost. And no verdict against the incumbent, since the acceptance rule belongs to the search loop.
    > **Note:** **A stale paragraph in ADR 0022, fixed on this branch.** Its Consequences bullet "The draw order changes" said a split draws "one `u_j` per live predecessor plus one fibre per live outbound arc". That contradicted its own Resolved section and `_split_state`, which draw for *every* predecessor and destination, so that the draw count depends only on `S`. The bullet now says so.
